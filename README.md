- 状態入力機能
    - ユーザーが自身の状態を入力する
        - 入力項目
            - 疲労度(0~100)
            - ストレス(0~100)
            - 睡眠時間
            - 外出していない日数
                - リフレッシュできたと思えない外出は外出していないものとする
                - 日中/夜なのかでもスコアが違うものとする
                    - 太陽の日や人との交流・視認ができるのは日中なので夜より比較してスコアが高いものとする
                        - 例
                            - 日中の外出 = 1日カウント / 夜の外出 = 0.5日カウント
            - 作業
                - 作業
                - 作業の大変さ
            - 気分
                - 選択式
                    - やる気がない/気分が沈んでいる/普通/元気
            - 各アクティビティの最終実施日
                - 例：本日 - 最終実施日 = 未実施日数

- 推奨度算出機能
    - 入力されたパラメータから推奨度を算出する
        - 対象アクティビティ
            - サウナ
            - 映画
            - カラオケ
        - 各アクティビティの算出方式は違うものとする
    - 算出方式(初期)
        - 重みづけによるルールベース
            例：
            ```
                サウナ推奨度 = 0.4 * ストレス + 0.3 * 疲労度 + 0.3 * 未実施日数                                     
                映画推奨度   = 0.2 * ストレス + 0.2 * 疲労度 + 0.3 * 未実施日数 + 0.3 * 気分
                                        
                カラオケ推奨度 = 0.3 * ストレス + 0.1 * 疲労度 + 0.3 * 未実施日数 + 0.3 * 気分
            ```
            - 重みの根拠は後に決める
- 可視化機能
    - 表示内容
        - 各アクティビティの推奨度(%)
            - 100%を超えてもいいものとする
            - アクティビティに行きたい度が指数関数的なグラフになっている
                - 緩やかでも急速でもいい
            - 時系列グラフ(状態の変化)
            - レーダーチャート
- 履歴管理機能
    - 入力履歴(入力したパラメーターなど)の保存
- 行動ログ機能
    - 実際に行動したか記録
    - 満足度入力
        - MVP内では、記録・表示のみ(将来の機械学習インプット用)

## 開発における制約
- Ruby / Ruby on Railsの理解を深めるため、AI エージェント CLIによる自動コーディングは禁止
- コード / ドキュメント参照・公式ドキュメントの読み込みは許可
- コピー&ペーストは極力避ける
- テストコードの整備
- ログや通知、テストでN+1問題を検出可能にする仕組み(検討中)
- 必ずISSUEを作成してから、そのISSUEに対応するPRを作成すること
- PRは手書きで書くこと(ghコマンド禁止)
